====================================================
ARSITEKTUR & KONVENSI (wajib diikuti persis)
====================================================
Struktur folder:
app/
├── data/
│   ├── local/entity/ (Vehicle, FuelLog, ServiceLog, VehicleDocument)
│   ├── local/dao/ (Room DAO per tabel)
│   ├── local/AppDatabase.kt (Room singleton)
│   ├── repository/ (query logic, return Result<T> / sealed Resource)
│   └── model/ (data class UI model)
├── ui/ (onboarding, vehicle, home, fuel, service, docs, scan, notifications, 
│        reports, profile, common/adapter, common/viewmodel)
├── util/ (Formatters, ImageHelper, ReceiptParser, ExportHelper)
└── service/ (NotificationScheduler)

Aturan wajib:
- Repository return Result<T> atau sealed class Resource — error & data harus 
  terpisah jelas, tidak boleh melempar exception mentah ke UI layer.
- MVVM flow: UI Event → ViewModel → StateFlow/LiveData → Fragment observe.
- RecyclerView WAJIB pakai DiffUtil untuk update list, tidak boleh notifyDataSetChanged() 
  polos.
- ViewBinding di setiap Fragment/Activity.
- Foto disimpan di app-specific directory, di-compress ke 1280px / kualitas 80% 
  sebelum disimpan.
- Format currency: Formatters.currency(value) → "Rp 1.250.000"
- Format date: Formatters.date(date) → "dd MMMM yyyy", locale id_ID
- Bahasa UI: Indonesia, konsisten di semua pesan (termasuk error message, jangan 
  campur teknis bahasa Inggris).

====================================================
LANGKAH KERJA (urutan wajib)
====================================================

TAHAP 1 — DATABASE LAYER
1. Buat 4 Entity Room sesuai skema:
   - vehicles (master kendaraan, multi-kendaraan per device, foto kendaraan)
   - fuel_logs (link vehicle_id, harga/liter, tanggal)
   - service_logs (link vehicle_id, kategori servis, next_service_date)
   - vehicle_documents (jenis: STNK/BPKB/SIM/Pajak/Asuransi, expiry_date)
   - (opsional) expense_categories
2. Buat DAO per tabel dengan query yang dibutuhkan UI (list, detail, insert, 
   update, delete, query khusus seperti "dokumen yang expire dalam 30 hari").
3. Buat AppDatabase singleton (Room), termasuk migration strategy dasar jika 
   diperlukan untuk pengembangan lanjut.
4. Setelah Entity/DAO selesai, laporkan skema final sebelum lanjut ke repository 
   (supaya bisa dicek dulu relasinya benar).

TAHAP 2 — REPOSITORY LAYER
1. Buat Repository per domain (VehicleRepository, FuelRepository, 
   ServiceRepository, DocumentRepository) yang membungkus DAO.
2. Semua fungsi return Result<T> atau sealed Resource (Loading/Success/Error) — 
   ikuti pola yang konsisten di semua repository.
3. Sertakan logic kalkulasi yang disebut di fitur (misal ringkasan konsumsi BBM, 
   total biaya) di layer ini, bukan di ViewModel/UI.

TAHAP 3 — VIEWMODEL LAYER
1. Buat ViewModel per fitur (mengacu ke folder ui/common/viewmodel), sambungkan 
   ke Repository terkait.
2. Expose data via StateFlow/LiveData sesuai konvensi UI Event → ViewModel → 
   State → Fragment observe.
3. Untuk data lintas Fragment (misal kendaraan yang sedang dipilih), gunakan 
   Shared ViewModel scope ke NavGraph/Activity — JANGAN duplikasi state di 
   banyak ViewModel terpisah.
4. Sambungkan ke Fragment yang SUDAH ADA — ganti dummy data yang sebelumnya 
   dipakai di tahap UI dengan observe ke ViewModel ini. Jangan ubah layout, 
   cukup sambungkan binding-nya.

TAHAP 4 — NOTIFIKASI LOKAL (ikuti spesifikasi persis)
1. Jadwalkan 3 slot notifikasi (H-7, H-1, H-0, jam 09:00 waktu lokal) setiap 
   kali record dengan tanggal jatuh tempo disimpan/diubah:
   - ServiceViewModel.addOrUpdate() → schedule pakai next_service_date
   - ServiceViewModel.delete() → cancel notif terkait
   - DocumentViewModel.addOrUpdate() → schedule pakai expiry_date
   - DocumentViewModel.delete() → cancel
2. Slot yang sudah lewat saat scheduling di-skip otomatis.
3. ID namespacing WAJIB persis format ini (anti-collision):
   - service log: 10_000_000 + (serviceId * 10) + dayCode
   - vehicle document: 20_000_000 + (documentId * 10) + dayCode
   - dayCode ∈ {0, 1, 7}
4. Gunakan AlarmManager.setExactAndAllowWhileIdle atau WorkManager 
   (PeriodicWorkRequest) sesuai kebutuhan toleransi.
5. Daftarkan BroadcastReceiver boot (RECEIVE_BOOT_COMPLETED) di AndroidManifest.xml 
   agar antrian notif survive restart device.
6. NotificationsFragment (yang sudah ada UI-nya): sambungkan data gabungan 
   service log (next_service_date mendatang) + document (expiry_date ≤30 hari), 
   urut ascending berdasarkan daysUntil. Card ≤7 hari pakai tint merah (tintRose), 
   sisanya amber — style ini kemungkinan sudah ada di layout, cukup sambungkan 
   logic pemilihan warnanya.

TAHAP 5 — BACKUP & RESTORE
1. Backup: copy database Room ke getExternalFilesDir(null)/kendaraanku_backup_<timestamp>.db
2. Restore: copy file backup terpilih, timpa database aktif, tampilkan Snackbar 
   minta user restart app.
3. Kirim: Intent.ACTION_SEND dengan FileProvider → share sheet.
4. Hapus: File.delete() lalu refresh list.
5. Catatan eksplisit: backup HANYA database, foto (struk, foto kendaraan) belum 
   ter-include — pastikan ini dikomunikasikan jelas ke user di UI (cek apakah 
   sudah ada disclaimer di layout, kalau belum, laporkan sebagai catatan, jangan 
   menambah UI baru tanpa konfirmasi).

TAHAP 6 — OCR SCAN NOTA
1. Integrasikan CameraX untuk capture foto struk.
2. Proses lewat Google ML Kit Text Recognition.
3. Parse hasil OCR (total, tanggal, nama bengkel/SPBU) via util/ReceiptParser.kt 
   ke form yang sudah ada (form Fuel/Service) — isi otomatis field yang berhasil 
   terdeteksi, biarkan field yang gagal terdeteksi tetap kosong untuk diisi manual 
   (jangan biarkan OCR gagal membuat seluruh form error).

TAHAP 7 — EKSPOR LAPORAN
1. PDF via iText/PdfDocument API, CSV via OpenCSV.
2. Sambungkan ke Reports screen yang sudah ada UI-nya.

TAHAP 8 — PERMISSION
Pastikan semua permission berikut didaftarkan di AndroidManifest.xml dan 
di-request pada waktu yang tepat:
- CAMERA (foto kendaraan & scan nota)
- READ_MEDIA_IMAGES (Android 13+) / READ_EXTERNAL_STORAGE (≤Android 12)
- POST_NOTIFICATIONS (Android 13+) — request sekali di MainActivity.onCreate()
- RECEIVE_BOOT_COMPLETED
- SCHEDULE_EXACT_ALARM, USE_EXACT_ALARM

TAHAP 9 — NAVIGATION WIRING
1. Pastikan MainActivity pakai BottomNavigationView + NavHostFragment dengan 
   4 tab (Home, Kendaraan, Laporan, Profil) — ini kemungkinan sudah ada dari 
   tahap UI, verifikasi saja.
2. Tombol back: OnBackPressedCallback — dari tab non-Home ke Home, dari Home 
   ke moveTaskToBack.
3. Safe Args untuk passing data antar Fragment.
